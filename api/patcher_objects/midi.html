.borax#

Reports statistics about a stream of notes: serial number, voice, how many notes are sounding, durations and the time between attacks.

Dart:

Obj.mBorax

Kind:

Control-rate

Each pair that arrives is a note-on when its velocity is not 0, and a note-off when it is 0. The object measures the notes; it does not pass them on, so wire it beside the path the notes take, not into it.

Outlets

Not every outlet fires on every message:

  • A note-on sends the delta pair (when there was an earlier note-on), then velocity, pitch, polyphony, voice and serial.

  • A note-off sends duration and note-off count, then velocity 0, pitch, polyphony, voice and serial.

  • delta sends only the delta pair: the time since the last note-on, right now. Before the first note-on it sends nothing.

The serial is sent last and is the same at the attack and the release of a note, so it identifies the note. Voices are the lowest free number from 1, as .poly numbers them. A pitch played twice takes two voices, and the releases close them oldest first. Durations and deltas are measured in milliseconds with sub-millisecond precision, on the same clock .timer uses.

Reset

A bang on the right inlet sends a full note-off report for every note still sounding, in voice order, then sets every counter back to 0 and forgets the last note-on, so the next note-on reports no delta.

Limits

At most 128 notes are tracked at once. A note-on with 128 notes sounding is ignored, and so is a note-off for a pitch no voice holds. Pitches and velocities are not clamped.

.flush#

Passes pitch/velocity pairs through and remembers which notes are sounding. A bang releases them all with velocity 0.

Dart:

Obj.mFlush

Kind:

Control-rate

Use it between the logic that plays notes and the object that sends them. A pair with a velocity other than 0 marks the pitch as sounding, a pair with velocity 0 clears it, and every pair passes through unchanged.

Messages

  • bang: send pitch and velocity 0 for every note still sounding, from the lowest pitch up, and forget them. A second bang sends nothing.

  • clear: forget the sounding notes without sending anything.

  • <pitch> <velocity>: set the velocity, then play the pitch. This is the shape .midiparse sends from its note outlet.

The object has no channel. To release notes in a MIDI byte stream on the channels they were played on, use .midiflush after the formatters.

Pitches outside 0-127 pass through but are not tracked. When the patcher is cleared or destroyed, or the object is deleted, the object releases its sounding notes first.

.makenote#

Plays a note: sends a pitch and velocity now, and the same pitch with velocity 0 after a duration in milliseconds.

Dart:

Obj.mMakenote

Kind:

Control-rate

The velocity and duration inlets set the values for notes played after them; a note already sounding keeps its own. A velocity of 0 is a release in MIDI, so the pair passes through and nothing is scheduled. The velocity starts at 0, so give it as the first argument or send one before playing:

[.makenote 100 500]   60  =>  60 100 now, 60 0 half a second later

Messages

  • stop: release every sounding note now, in the order they were played.

  • clear: forget the sounding notes without releasing them.

  • <pitch> <velocity>: set the velocity, then play the pitch.

The duration is in milliseconds. A duration of 0 releases the note on the next audio block. Durations follow the engine’s audio clock: while the engine is paused, pending releases wait. Note values such as 4n and tick counts are not supported; they are ignored and the duration is left as it was.

A pitch played twice is two notes, each released after its own duration.

Limits

One .makenote holds at most 64 sounding notes. Past that, a new note is refused completely: nothing is sent. The patcher also holds at most 128 pending timed messages, shared with .pipe, .delay and the other timing objects; when that runs out, the note is released at once instead of after its duration.

When the patcher is cleared or destroyed, or the object is deleted, it releases its sounding notes first.

.midiflush#

Passes a MIDI byte stream through and remembers which notes it left sounding. A bang sends a note-off for each of them.

Dart:

Obj.mMidiflush

Kind:

Control-rate

Put it in a MIDI byte stream, for example between the formatters and .midiout. Everything that arrives passes out unchanged, in the form it arrived in. On the way through, the object follows the stream and remembers which notes are sounding on which channel.

A bang sends a note-off for every note still sounding, as numeric lists such as 128 60 0, ordered by channel and then pitch, and forgets them.

The stream is decoded the way .midiparse decodes it, so notes sent under running status are tracked, a clock byte between two data bytes does not break a note, and bytes inside a system-exclusive dump are never read as notes. Both forms of a release clear a note: a note-off, and a note-on with velocity 0.

The inlet reads numeric byte lists, the binary messages the MIDI sender objects build, and single ints. A numeric list holding a number outside 0-255 is dropped whole.

.midiout’s allnotesoff is a controller message that many devices ignore; .midiflush sends a real note-off for each note. When the patcher is cleared or destroyed, or the object is deleted, it flushes first.

.midiformat#

Builds raw MIDI messages from notes, controllers, program changes, pressure and pitch bend. The inverse of .midiparse; each message leaves as a list of byte values.

Dart:

Obj.mFormat

Kind:

Control-rate

Every inlet except the channel sends a message at once, on the channel the channel inlet holds (1 until set). The output is a list of byte values, such as 144 60 100, one message per list.

Inlets

  • note: <pitch> <velocity>. A bare pitch is sent with velocity 0, which is a release. Releases are sent as note-ons with velocity 0, never as note-off messages.

  • poly pressure: <pitch> <pressure>; a bare pitch sends pressure 0.

  • control change: <controller> <value>; a bare number sends value 0.

  • program change: 1-128, the numbering .pgmin and .midiparse report.

  • aftertouch: one pressure value for the channel.

  • pitch bend: 0-127, the coarse byte, with 64 at rest. The fine byte is sent as 0.

  • channel: 1-16, stored only.

  • raw: byte values passed straight to the outlet, so the system-exclusive and clock messages .midiparse sends from its rightmost outlet can be put back.

Values are clamped to the range MIDI allows, except on the raw inlet, where a value outside 0-255 is dropped. A raw list is cut at 128 bytes.

Because .midiparse reports a note-off as velocity 0 and pitch bend as the coarse byte, a stream taken apart and put back together loses note-off release velocities and the fine bend byte.

.midiin#

Raw MIDI input. Every byte received on a MIDI input port leaves the outlet as an int, in arrival order and uninterpreted.

Dart:

Obj.mIn

Kind:

Control-rate

Availability:

MIDI device only

Note

Only available when libYSE is built with YSE_ENABLE_MIDI_DEVICE (on by default on Windows and Linux desktop builds). On macOS and Android the option is off and this object is not registered, so a patch that uses it is not portable to those platforms. Check PatcherObjectType.requiresMidiDevice or Obj.isValid at runtime.

The bytes arrive exactly as the device sent them, so a note-on is three ints and a system-exclusive dump is as many ints as it has bytes. To work with whole messages, use .xmidiin; to decode them, wire .midiin into .midiparse.

Every MIDI input object

The objects that receive from a MIDI device (.midiin, .xmidiin, .notein, .ctlin, .sysexin and the others) share these rules:

  • The first argument is the input port, counted from 0. .midiinfo lists the ports by name. Several objects can listen to one port; each receives every message.

  • A port that cannot be opened, because the device is missing or another program holds it, leaves the object silent. The patch still loads.

  • Changing the port argument while the patch runs recreates the object.

  • Messages that arrive between two audio blocks reach the patch at the start of the next block. At most 64 short messages (512 bytes) are handed out per block; the rest wait for the next block, so a long dump arrives over several blocks.

  • These objects exist only in builds with MIDI device support, which includes the Windows and Linux builds.

Objects that decode channel messages (.notein, .ctlin, .bendin, .pgmin, .touchin, .polyin, .rpnin, .nrpnin and the .x input objects) also share these:

  • The second argument is the channel to listen to, 1-16. 0, the default, listens to all channels.

  • Channels are reported as 1-16. The channel outlet is there even when the object listens to one channel, and then always reports that channel.

  • The outlets fire from right to left, so the channel and the other values are out before the leftmost outlet triggers anything.

Limits

A message of up to 8192 bytes arrives whole. A longer one is dropped entirely and logged, never passed on cut short. Messages are also dropped, and logged, when they arrive faster than the patch takes them. At most 8 input ports can be open at once, and at most 8 objects can listen to one port.

.midiinfo#

Lists the machine’s MIDI ports. A bang sends the number of ports, then an index and a name for each, so a patch can find a device by name.

Dart:

Obj.mMidiinfo

Kind:

Control-rate

Availability:

MIDI device only

Note

Only available when libYSE is built with YSE_ENABLE_MIDI_DEVICE (on by default on Windows and Linux desktop builds). On macOS and Android the option is off and this object is not registered, so a patch that uses it is not portable to those platforms. Check PatcherObjectType.requiresMidiDevice or Obj.isValid at runtime.

Input ports and output ports are numbered separately: input port 1 and output port 1 are unrelated devices. The direction argument chooses which list a bang reports.

Messages

  • bang: send the number of ports, then for each port its index and then its name.

  • input, output: switch which list is reported.

  • refresh: scan the machine again, for example after a device was plugged in. The scan runs in the background, and the full listing is sent again when it finishes, from the next audio block.

The ports are scanned when the object is created; a bang reports that scan until refresh takes a new one. Names are sent whole, spaces included.

Limits

At most 32 ports are listed per direction, and names are cut at 63 characters. At most 16 .midiinfo objects can use refresh at the same time. Only available in builds with MIDI device support.

.midiout#

Sends MIDI messages to an output port. Each list on the inlet is one message, as byte values or as built by the MIDI sender objects; a few words send common channel-mode messages.

Dart:

Obj.mOut

Kind:

Control-rate

Availability:

MIDI device only

Note

Only available when libYSE is built with YSE_ENABLE_MIDI_DEVICE (on by default on Windows and Linux desktop builds). On macOS and Android the option is off and this object is not registered, so a patch that uses it is not portable to those platforms. Check PatcherObjectType.requiresMidiDevice or Obj.isValid at runtime.

Input

Each list is sent as one MIDI message, at its own length, so a program change goes out as two bytes and a system-exclusive dump as a whole. Two forms are accepted:

  • numeric, 144 60 100: what .midiformat, .sxformat, .xmidiin and .seq send;

  • binary: what .noteon, .bendout, .rpnout and the other sender objects build.

A numeric list with a number outside 0-255, or longer than 256 bytes, is not sent.

Messages

  • allnotesoff: controller 123 (all notes off) on all 16 channels.

  • reset: controller 121 (reset all controllers) on all 16 channels.

  • omni on, omni off, poly on, poly off, local control on, local control off: the matching channel-mode message on channel 1.

Opening the port

The port opens when the first message arrives, not when the object is created, so a patch loads on a machine without its devices. The port is opened in the background, and messages sent before it is open are dropped, including the first one. If the port cannot be opened, every message is dropped.

Sending never blocks the audio thread: messages are handed to a separate thread, which normally sends them within a millisecond, in order. If that queue is full, a message is dropped.

At most 64 .midiout objects can exist at once; a further one never opens its port. Only available in builds with MIDI device support.

Dart:

Assigns notes to a numbered pool of voices. Each note-on takes a free voice, and its release comes out with the same voice number.

Dart:

Kind:

Wire the voice outlet into .route or .gate to send each note to its own voice chain. The voice number is sent last, after the velocity and pitch, so it is the value that triggers.

Allocation

  • A note-on takes the lowest free voice.

  • A note-off frees the voice holding that pitch and sends the same voice number with velocity 0. A pitch played twice takes two voices; the releases free them oldest first.

.sustain#

A sustain pedal for pitch/velocity pairs. While the pedal is down, releases are held back; lifting it sends them all.

Dart:

Obj.mSustain

Kind:

Control-rate

A note-on always passes straight through. A note-off (velocity 0) passes through with the pedal up, and is held back with the pedal down. Lifting the pedal sends every held note-off, from the lowest pitch up.

Messages

  • sustain 1, sustain 0: press or lift the pedal, as the right inlet does.

  • flush: send every held note-off now and leave the pedal where it is.

  • clear: forget the held note-offs without sending them.

  • <pitch> <velocity>: set the velocity, then play the pitch.

A key played again while its release is held sounds again, and the held release still goes out when the pedal lifts. Pitches outside 0-127 are never held.

Placed before a .flush, it leaves the .flush tracking what is really sounding. When the patcher is cleared or destroyed, or the object is deleted, it sends its held note-offs first.

.sxformat#

Builds a system-exclusive message from a template of constant bytes, placeholders filled from the inlets, and an optional checksum.

Dart:

Obj.mSxformat

Kind:

Control-rate

The arguments are the template, one token per byte:

  • a number 0-255: a constant byte,

  • $i1 to $i9: a byte taken from an inlet; $i1 is the left inlet,

  • sumstart: sends nothing, and starts the checksum region,

  • sum: a checksum byte that makes the region’s total a multiple of 128, as Roland devices expect. Without sumstart, the region is everything before it except a leading 240.

The object has one inlet for each placeholder up to the highest one used. The left inlet sends the message; the others only store. A list on the left inlet fills $i1, $i2 and so on, then sends. A bang sends with the stored values.

A negative value leaves its byte out, so one template can cover a short and a long form of a message. A value above 127 is clamped to 127. A placeholder that has not received a value is 0.

[.sxformat 240 67 16 0 $i1 $i2 247]   5 99 -> left inlet  =>  240 67 16 0 5 99 247

The message leaves as a list of byte values for .midiout. Start it with 240 and end it with 247; the object does not add them.

Limits

A template holds at most 256 tokens; the rest is cut, with an error in the log. A token that is not a byte, a placeholder, sumstart or sum is skipped, with an error in the log.
