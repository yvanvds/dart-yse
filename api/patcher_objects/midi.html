MIDI#

Formatting, parsing and note handling for MIDI, and MIDI device I/O.

45 objects. Every entry is pulled directly from the engine registry, which reads the ADD_DESCRIPTION / INLET_DOC / OUTLET_DOC / PARAM_DOC macros in the libYSE source. The ~ prefix marks DSP / audio-rate objects; . marks control-rate objects. For long-form notes, see the libYSE page for this category.

Note

Objects marked MIDI device only below hold a MIDI device port. They exist only in builds with YSE_ENABLE_MIDI_DEVICE — not on macOS or Android.

.bendin#

MIDI pitch-bend input at 7-bit resolution: reports the pitch wheel as 0-127 with 64 at rest. .xbendin reports the full 14 bits.

Dart:

Obj.mBendin

Kind:

Control-rate

Availability:

MIDI device only

Note

Only available when libYSE is built with YSE_ENABLE_MIDI_DEVICE (on by default on Windows and Linux desktop builds). On macOS and Android the option is off and this object is not registered, so a patch that uses it is not portable to those platforms. Check PatcherObjectType.requiresMidiDevice or Obj.isValid at runtime.

INT

0-127

The wheel position: 0 fully down, 64 at rest, 127 fully up.

1

INT

1-16

The channel the message arrived on, 1-16. Sent before the outlets to its left.

Parameters

Name

Default

Range

Description

port

0

0-7

MIDI input port to listen to, counted from 0; .midiinfo lists them. A port that cannot be opened leaves the object silent, and the patch still loads.

MIDI channel to listen to, 1-16, or 0 for all channels. Any other value means all channels. The channel outlet stays either way.
